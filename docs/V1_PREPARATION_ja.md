# v1.0 実装準備とE2Eの進め方

0.17.2は、V1-01〜V1-05の**修正・検査・証拠収集の実装準備**です。
v1.0公開済み、最終実機E2E済み、supported構成確立済み、という意味ではありません。

## 工程ごとに実機E2Eを繰り返す必要はありません

V1-01〜05をまとめて実装し、途中では契約・スキーマ・通信・永続化・中断復旧・
配布物の自動回帰テストを行います。その後、最終1.0.0のメタデータと配布物を固定し、
同じ配布物に対して実機E2Eを一つの検証工程として実施します。

ただし一つの検証工程でも、正常な新規変更・実際のStart拒否・アイドル状態からの
取消確定は**それぞれ新規IDで2回**必要です。取消済みタスクのpermission要求、
未操作・No・cancel・Yes・timeout・stale・duplicate応答も確認します。
最終E2E後にコード、同梱Skill、契約台帳、バージョンなどを変更すれば別のビルドです。
旧結果を最終配布物の結果に読み替えません。

## 今回追加する仕組み

スキーマの説明キーと本当のフィールド名・定数を区別し、CLIの継承された引数、
型・既定値・排他条件も検出します。入力だけでなく、応答・拒否・エラーとSDK署名を
契約として列挙し、独立した期待値と照合します。保存形式と既存履歴ハッシュは維持します。

CIでwheel/sdistを一度だけ作り、4つの参照環境で同じ配布物をクリーンインストールして
検証します。最小依存関係2構成も保持します。ジョブ内の収集時にはCI成功と断定せず、
全体完了後のGitHub結果と照合して完了記録を作ります。

サポート表v2はホストのフォーム通信とプロバイダーの実行を分離します。
旧表は履歴としてそのまま保存し、Claude Code 2.1.284のconditionalや他ホストの
unverifiedを自動昇格させません。実機観測なしで合格扱いにはしません。

出荷検査は配布物・環境・CI・実機証拠・永続保管・公開承認の完全なハッシュを
検査します。不足・不一致・未完了・省略テストがあれば停止します。この検査器は
公開、provider呼び出し、runtime DB操作、権限変更を実行しません。

## 残る完了条件

実装と自動テストが成功しても、V1-04の最終実機認定とV1-05の最終出荷証拠は別です。
最終1.0.0候補の準備、所有者が決める配布条件・公開先、実機観測と異常の整理、
永続的な証拠保管、配布物に紐付く明示的な公開承認が必要です。
ライセンスや公開先をこの修正で勝手に選択せず、実環境更新・タグ・公開も行いません。

詳細は[英語の準備手順](V1_RELEASE_PREPARATION.md)、[最終E2E](V1_LIVE_E2E.md)、
[公開契約](PUBLIC_CONTRACTS.md)、[確定設計](V1_STABLE_CONTROL_PLANE.md)を参照してください。
